# OceanEye Sentinel 2.0 - 90-second pitch

Single script for two uses: the in-app Pitch Mode (`?pitch=1`, built on the existing `tourSteps` / `renderTourStep`) and the submission video voiceover. The on-screen caption is the voiceover, word for word. Every spoken number is a `{path|format}` placeholder resolved from `stats.json`; none is typed into prose. Drop-in code: `pitch_steps.example.js` (same folder).

Totals: 8 beats, 90.0 s. Words (whitespace tokens of the rendered text, a number counts as one): EN 215 (2.39 words/s) and ES 229 (2.54 words/s) with every feature present; EN 209 and ES 222 on the fallbacks. Rendered by `resolvePitchSteps` against `build_stats.py` output for the committed benchmark artifact, not typed.

The pitch no longer speaks a "values per case" number: the legacy validator extracts latitude, longitude, distance, length and RCS but compares only the first four (RCS is extracted and never checked), so "5 values" would overstate what is checked.

Cost basis: list prices from https://dev.meta.ai/docs/pricing-rate-limits, read 2026-10-29: Wonder $4.00 input / $20.00 output per 1M tokens, Spark $1.25 / $4.25 (also Muse Image $0.01 per image and SAM 3.1 $2.50 per 1,000 images, not spoken). https://dev.meta.ai/docs/reasoning, read the same day, says reasoning tokens are billed at the visible output rate and are reported in `completion_tokens_details.reasoning_tokens`. The artifact is consistent: in all 60 usage records `total_tokens` = `prompt_tokens` + `completion_tokens` and `reasoning_tokens` <= `completion_tokens`, so charging completion tokens at the output price covers reasoning. It stays an estimate (list price, no cached-input discount, one run), hence "estimated" in the VO. Store the prices and the date in `stats.json` next to the ratio (the generator's `pricing` block does).

Formats used by the template: `g1` one decimal with trailing .0 dropped (comma in ES), `s1` milliseconds to seconds then `g1`, `invpct` 100 divided by the ratio as a whole number, `runs` "One run" / "N runs". Counts are printed as they are.

What the pass count means (do not describe it more strongly): the check is a regex comparison inside `backend/app/legal/neuro_symbolic_validator.py`. Adherence is 100 minus 15 per discrepancy; a raw pass is zero discrepancies; omitting a value is not penalised. The 30 scenarios and their reference values are typed by hand in `legal_eval_harness.py` (`SCENARIOS_30`), so they are given values, not measurements. Known false positives of the legacy extractors (for example "millas" read as a length in metres, "1SDV" read as a latitude) mean 26 / 19 and 98 / 92 may be distorted in either direction until the artifact is regenerated with a fixed validator. The stored narrative preview is 240 characters, so failures cannot be audited from the artifact alone.

## Pitch Mode behaviour (code in `pitch_steps.example.js`)

- `?pitch=1` autostarts after `init()` has loaded vessels and SAR detections. `&lang=es|en` forces the language, otherwise `navigator.language`. `&step=N` starts at beat N.
- Stats are fetched from `../data/stats.json`. From `/OceanEye-hackaton-meta/app/` that is `/OceanEye-hackaton-meta/data/stats.json`, so publish it as `docs/data/stats.json` (what GitHub Pages serves). The generator writes `frontend/data/stats.json`; copy it byte for byte to `docs/data/` and to the repo-root `data/`, so each of the three identical `app/index.html` copies (root, `docs/app`, `frontend/app`; same sha256 `2a616694…f16f384`) finds its neighbouring `data/`. The snapshot has no sync script: copy by hand and compare with `cmp`. The same rule holds for `arena_replay.json`, `sam_masks.json` and `sam_chips/`. Never `/data/...` (it points outside the project subpath). A non-200 response or a parse error is treated as missing stats.
- Space pauses and resumes (remaining time is kept). ArrowRight / ArrowLeft move, Esc exits and stops the clock, so no later step renders or switches view. Keys are ignored while typing in an input, textarea or select, with Ctrl / Meta / Alt held, and on key repeat. Esc does not set `oceaneye_tour_completed` and sends no request to the API (the legacy `closeTour` posts to `API_BASE`).
- `prefers-reduced-motion: reduce`: starts paused, uses instant scrolling, and nothing advances until Space or the arrow keys.
- Reuses the legacy modal: replaces the contents of `tourSteps` with 8 slots, fills slot i when beat i is shown, overrides `nextTourStep`, `prevTourStep`, `closeTour` while active, and restores them (and the Spanish button labels) on exit. The three modal buttons are relabelled to the pitch language. A cleaner option is `renderTourStep(idx, steps)` taking the array as a parameter.
- All captions are written with `textContent` by `renderTourStep`; stats values only enter the text if they are finite numbers, so there is no HTML injection path.
- The pitch backdrop is lightened (no blur, 0.35 alpha) and non-blocking so the product stays visible on video.
- Map view: `map.setView([-45.5, -59.5], 6.5)` takes `[lat, lng]` (Leaflet order) and is the same call the app already makes at `index.html` lines 2264 and 3504. The injected targets lie at latitude -46.12 to -45.16 and longitude -60.50 to -59.84.
